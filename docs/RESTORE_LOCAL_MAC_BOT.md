# Возврат Aisora к локальному Telegram-боту на Mac

## Что уже есть в main

Локальный режим не удалялся. При обычном запуске на Mac `src/main.ts` импортирует `AppModule`: NestJS, реальный ABU AIS Playwright adapter, PostgreSQL, Redis/BullMQ и **TelegramBotService** с `bot.start()` (long polling). Облачный `VercelAppModule` активируется только при `VERCEL=1` или `AISORA_RUNTIME=vercel`.

**Не нужно** сбрасывать main до старых коммитов: это потеряет полезные исправления чтения АИС. Облачная версия не мешает работе отдельного прежнего Telegram-бота на Mac.

## Запуск на Mac

1. Открой локальную папку проекта Aisora. Проверь, что PostgreSQL и Redis запущены. В рабочей папке должны быть `.env`, `node_modules` (или установи `pnpm install`).
2. Убедись, что в `.env` прописано:
   - `DATABASE_URL` — **твоя прежняя локальная** PostgreSQL, если хочешь сохранить старые данные; не заменяй случайно на Neon.
   - `REDIS_URL` — адрес локального Redis.
   - `TELEGRAM_BOT_TOKEN` — токен **старого Telegram-бота**, которым пользовался до Aisora Cloud Test.
   - `CREDENTIALS_MASTER_KEY` — **старый ключ от локальной БД**, если раньше вводил /connect и хочешь восстановить расшифровку; не заменяй новым облачным ключом.
   - `AIS_AUTOMATION_APPROVED=true` — только при наличии разрешения на автоматизированное read-only чтение АИС.
   - `AIS_BROWSER_HEADLESS=false` — чтобы видеть работающий браузер Playwright.
3. Убедись, что переменные `VERCEL` и `AISORA_RUNTIME=vercel` **не установлены** локально.
4. Запуск:
   ```bash
   pnpm install
   pnpm start:dev
   ```
5. Открой **старого Telegram-бота**, отправь `/start`, затем `/status`, `/sync`. Если сохранённого входа нет, выполни `/connect` в личном чате.
6. Проверяй синхронизацию в браузере Mac, Telegram и логах NestJS. Не запускай второго экземпляра polling для **того же токена**: Telegram выдаст конфликт `getUpdates`.

## Нужно ли запускать ngrok?

**Нет**, если вся связь с ботом идёт через Telegram long polling (grammY `bot.start()`): NestJS сам опрашивает Telegram, входящий URL не требуется.

Запускай ngrok отдельно лишь при необходимости опубликовать локальный REST API/webhook для других приложений. При этом ngrok не меняет исходящий IP Playwright: АИС видит интернет-подключение Mac.

## Важно о двух ботах и двух базах

- Старый локальный бот и **Aisora Cloud Test** должны использовать **разные** Telegram-токены.
- Облачный webhook на Vercel не мешает локальному polling **другого** бота.
- Локальная PostgreSQL и Neon — разные базы; данные и секреты не синхронизируются автоматически.
- Если запускаешь старого бота локально с его прежней БД, не нужно повторно вводить /connect, если ключ шифрования и сохранённая сессия ещё действуют.
- Не присылай токены, пароль АИС и `CREDENTIALS_MASTER_KEY` в чат, коммиты и скриншоты.
- Можно просто перестать использовать Aisora Cloud Test; удалять GitHub Actions, Neon и Vercel не обязательно. Для безопасности, когда облако больше не нужно, отдельно отзови PAT `Aisora Cloud Sync` в настройках GitHub; это отключит облачный /sync.

## Устранение проблем

- **Конфликт polling**: останови другой локальный процесс с тем же `TELEGRAM_BOT_TOKEN`.
- **Redis/PG ошибка при старте**: запусти свои локальные сервисы; проверяй URL в локальном `.env`.
- **Сессия/пароль не читаются**: проверь, что установлен прежний `CREDENTIALS_MASTER_KEY`; если старый ключ потерян, потребуется новый /connect.
- **В браузере не видно Playwright**: проверь `AIS_BROWSER_HEADLESS=false`.
- **Локальный запуск по ошибке открывает облачный HTTP-only модуль**: удали `AISORA_RUNTIME=vercel` и `VERCEL=1` из локального окружения.
