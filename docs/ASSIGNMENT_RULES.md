# Правила обнаружения заданий

Документ разделяет подтверждённое официальной инструкцией и правила, заданные владельцем проекта, которые ещё нужно проверить на реальном аккаунте.

## Общие принципы

- Учебная неделя, номер задания и срок сдачи — разные поля.
- Один источник не считается достаточным для окончательного статуса.
- Отсутствие оценки не доказывает отсутствие отправки.
- Любой неоднозначный статус маркируется `UNKNOWN`, а не `NOT_SUBMITTED`.
- Массовая подготовка старых задолженностей запрещена без выбора студента.

## СРО

Подтверждено официально:

- СРО имеет отдельную вкладку.
- На вкладке показываются виды СРО и неделя предоставления.
- Передача выполненной СРО выполняется через эту вкладку.
- Методические материалы могут находиться в «Файловом ресурсе» и контенте дисциплины.

Задано владельцем и требует проверки:

- запись в журнале сама по себе не означает, что задание доступно для сдачи;
- главным источником обязательности является отдельная вкладка «СРО».

Правило обнаружения: создать задание СРО только при наличии отдельной записи СРО или после ручного подтверждения студента. Запись в журнале без доступной СРО — сигнал для проверки, не задолженность.

## СРСП / СРОП

Подтверждено официально:

- практические работы и СРСП отправляются через «Сообщения»;
- контент дисциплины может содержать задания СРОП/СРСП по неделям;
- сообщение может содержать тему, текст и файл.

Задано владельцем и требует проверки:

- тема обычно имеет вид `СРСП 2 неделя`;
- описание обычно пустое.

Правило обнаружения: материал в контенте создаёт кандидата на задание. Статус отправки проверяется по исходящим сообщениям, вложениям и, при наличии, оценке. Совпадение только по тексту темы — слабое доказательство.

## Лабораторные

Подтверждено официально: в файловых ресурсах могут находиться методические указания для лабораторных работ.

Задано владельцем и требует проверки:

- не каждый преподаватель требует отправку;
- при необходимости используется «Сообщения»;
- пример темы: `Lab 3, 4 неделя`.

Правило обнаружения: лабораторный материал не становится обязательной отправкой автоматически. Нужен признак требования в тексте/сообщении либо подтверждение студента.

Лабораторный отчёт должен содержать проверяемые результаты реального запуска. Генерация фиктивных скриншотов, выдаваемых за запуск программы, запрещена.

## Модель статуса

| Статус | Критерий |
|---|---|
| `DISCOVERED` | Найден материал или запись задания |
| `REQUIRES_CLARIFICATION` | Нельзя подтвердить обязательность/канал сдачи |
| `NOT_STARTED` | Обязательность подтверждена, работа не начата |
| `IN_PROGRESS` | Есть локальный черновик |
| `READY_FOR_REVIEW` | Результат готов, ожидает студента |
| `APPROVED` | Студент явно одобрил конкретную версию |
| `SUBMISSION_PENDING` | Разрешённая отправка поставлена в очередь |
| `SUBMITTED_UNVERIFIED` | Интерфейс принял действие, но нет независимого подтверждения |
| `SUBMITTED_CONFIRMED` | Есть подтверждённая запись/вложение с совпадающими признаками |
| `GRADED` | Есть оценка, связанная с заданием |
| `RETURNED` | Преподаватель вернул работу/запросил исправление |
| `UNKNOWN` | Данных недостаточно или они противоречат друг другу |

## Сопоставление

Использовать комбинацию: дисциплина, преподаватель, тип задания, учебная неделя, номер задания, нормализованная тема, имя/хэш файла, время отправки и идентификатор записи AIS (если он есть). Нечёткое совпадение не должно автоматически переводить работу в подтверждённо отправленную.

Источник подтверждённых пунктов: [официальная инструкция ABU](https://old.abu.edu.kz/uploads/4/271/266/8bba216f5f9eb50fe59aae6dc7e8399a.pdf).
