# Aisora — диагностика локальной синхронизации на Mac (Trace Viewer)

**Единственная рабочая ветка:** `main`. Стабильная исходная версия старого бота: tag `aisora-working-local-cc7f5b7`.

## Что записывается

При `AIS_SYNC_DIAGNOSTICS_ENABLED=true` Aisora после входа в АИС включает Playwright tracing в том же браузерном контексте, который использует локальный `AbuUniversityAdapter`.

Всё остаётся на Mac:

- `artifacts/sync-diagnostics/run-.../trace.zip` — полный **Playwright Trace Viewer**: шаги, клики, DOM-снимки, браузерные изображения и сетевые события. **Содержит приватные данные из АИС! Не загружать в ChatGPT, GitHub, облако или другие сервисы.**
- `artifacts/sync-diagnostics/run-.../report.json` — технический отчёт **без текстов страниц и заданий, логинов, паролей, токенов, идентификаторов пользователя и URL**: действие (без динамического названия дисциплины), тип элемента, role, число совпадений, время ожидания, время клика, тип ошибки и агрегированные сетевые счётчики.
- `node scripts/last-sync-diagnostics.cjs` — краткий список узких мест последней синхронизации.

Обход страниц, алгоритмы распознавания СРО/СРСП и отправка итогового сообщения остались неизменными. Trace записывается **после авторизации**, поэтому действия ввода логина/пароля не захватываются. Однако trace всё равно содержит содержимое авторизованных страниц и может содержать cookies/данные сессии в сетевой части. Храни только локально, удаляй, когда больше не нужен.

## Как запускать на Mac (старый Telegram-бот)

1. Сохрани свою рабочую точку `aisora-working-local-cc7f5b7` (она уже запушена в GitHub).
2. Дождись успешной проверки нового коммита в GitHub. В папке проекта: `git status`. Если нет локальных изменений, затем `git pull --ff-only origin main`. **Не делай `git reset --hard` и не меняй старый `.env` целиком.**
3. Добавь в **существующий** локальный файл `.env` строку:
   ```env
   AIS_SYNC_DIAGNOSTICS_ENABLED=true
   ```
   Оставь прежние `TELEGRAM_BOT_TOKEN`, `DATABASE_URL`, `REDIS_URL`, `CREDENTIALS_MASTER_KEY` и `AIS_BROWSER_HEADLESS=false`. Используй **старый**, а не облачный Telegram-бот.
4. Запусти локальный сервер обычным способом: `pnpm start:dev`. Никакие GitHub Actions, Vercel или ngrok для Telegram polling не требуются.
5. Отправь **старому** боту `/sync` и дождись окончания (или ошибки). Рядом с процессом NestJS появится строка `Local sync diagnostic files saved in ...`.
6. В терминале из папки Aisora запусти:
   ```bash
   node scripts/last-sync-diagnostics.cjs
   ```
   Команда покажет замедления и готовую команду открытия `trace.zip` в Trace Viewer.

## Как смотреть HTML и нажатия

```bash
pnpm exec playwright show-trace "artifacts/sync-diagnostics/run-ИМЯ_ЗАПУСКА/trace.zip"
```

Скопируй путь из вывода `node scripts/last-sync-diagnostics.cjs` — там будет точная команда без необходимости угадывать имя папки.

В Trace Viewer:
- **Actions**: выбери действие `click`, например выбор недели или переход в журнал.
- **Snapshot**: посмотри разницу DOM перед и после; клик подсвечивается на снимке.
- **Call / Source**: посмотри вызов и исходный TypeScript-файл.
- **Network**: проверь долгие AJAX-запросы.
- **Timeline**: установи, где Playwright ждёт дольше всего.

**Полный Trace Viewer — только на твоём Mac.** Для анализа в чате передавай `report.json`, вывод `node scripts/last-sync-diagnostics.cjs`, а при необходимости только вручную очищенные фрагменты HTML/скриншоты без ФИО, оценок, сообщений, токенов и идентификаторов. Для особо строгой приватности можно ограничиться текстовым отчётом.

## Объяснение причин задержек

В рабочем коде `waitForWeekContent()` ожидает смену недели и дополнительно ждёт `AIS_AJAX_SETTLE_MS`; `readContentDetails()` иногда повторно открывает неделю; `readSentMessages()` проходит сообщения последовательно. Это лишь **кандидаты на измерение**, не доказанные ошибки.

В `report.json` события `click` содержат только известные безопасные метки:
- `course-menu-toggle` / `course-select-menuitem` — раскрытие и выбор дисциплины;
- `week-select` — клик по ссылке недели (в коде `#li-${week} a`);
- `week-content-ready` — ожидание обновления AJAX/DOM недели;
- `content-details-open` — открытие условий задания;
- `sent-folder-open` / `sent-message-row-open` — отправленные сообщения;
- `sro-history-open` — просмотр ранее прикреплённых файлов;
- `request-spacing` — намеренная задержка между запросами;
- `stage` — основные этапы чтения из адаптера.

Этапы и действия могут перекрывать друг друга по времени, поэтому суммы длительностей нельзя считать общим временем синхронизации.

## Ограничения первого выпуска

- Записывается браузерная часть `readSnapshot()`; запись `trace.zip` завершается **до записи результатов в PostgreSQL**. Время сохранения БД и Telegram-ответа пока не измеряется этим отчётом.
- `trace.zip` создаётся только после успешного появления страницы входа или профиля. Если ошибка возникла до авторизации, Trace Viewer за этот запуск не создаётся.
- В режиме диагностики чтение структуры DOM добавляет небольшую нагрузку, поэтому длительности нужно сравнивать осторожно.
- Чтобы выключить диагностику, поставь `AIS_SYNC_DIAGNOSTICS_ENABLED=false` и перезапусти NestJS.
