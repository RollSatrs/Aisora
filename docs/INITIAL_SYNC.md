# Первоначальная синхронизация

## Цель

Построить снимок текущего обучения, сопоставить задания с отправками и оценками, а неопределённость сохранить явно. Синхронизация read-only и не запускает подготовку всех старых работ.

## Алгоритм

1. Проверить наличие действующей сессии. При необходимости попросить владельца вручную войти.
2. Зафиксировать момент синхронизации, часовой пояс `Asia/Almaty`, семестр и доступный диапазон недель.
3. Получить дисциплины и преподавателей.
4. Для каждой дисциплины последовательно прочитать:
   - указатель недель;
   - контент дисциплины и файловые ресурсы;
   - отдельную вкладку СРО;
   - исходящие/связанные сообщения;
   - журнал оценок.
5. Нормализовать каждое наблюдение, сохранив источник и время получения.
6. Сформировать кандидаты заданий и дедуплицировать по устойчивому ключу.
7. Сопоставить кандидаты с отправками, вложениями и оценками.
8. Рассчитать статус и уровень уверенности; противоречия переводить в `UNKNOWN`.
9. Сформировать три списка: подтверждённые задолженности, неопределённые случаи, подтверждённо выполненные.
10. Показать студенту результат и предложить выбрать старые задания для дальнейшей работы.

## Доказательства статуса

| Наблюдение | Сила | Вывод |
|---|---:|---|
| Исходящая запись с совпадающим вложением/идентификатором | Высокая | Вероятно отправлено; проверить устойчивость записи |
| Оценка, однозначно связанная с заданием | Высокая | Выполнено и оценено |
| Совпадающая тема сообщения без файла | Средняя | Требует проверки |
| Только оценка в недельной ячейке | Средняя/низкая | Может относиться к другой активности |
| Нет оценки | Нулевая | Нельзя делать вывод об отправке |
| Материал в контенте | Низкая | Кандидат, но не всегда обязательная отправка |

## Идемпотентность

- Один запуск синхронизации имеет `sync_run_id`.
- Наблюдение получает `source_fingerprint` из стабильных полей и хэшей контента.
- Повторное чтение обновляет `last_seen_at`, а не создаёт дубликат.
- Исчезновение записи не удаляет её сразу: ставится `not_seen_since`.
- Задание создаётся/обновляется через уникальный адаптерный ключ.
- Ручное решение студента не перезаписывается слабым автоматическим сигналом.

## Результат синхронизации

```text
Синхронизировано: N дисциплин, W недель
Подтверждённые задолженности: ...
Требуют уточнения: ...
Выполнено/оценено: ...
Ошибки и недоступные разделы: ...
```

## Условия остановки

Немедленно остановить сбор при CAPTCHA/MFA, блокировке, изменении условий доступа, неожиданном переходе на действие записи, повторяющихся ошибках авторизации или признаке превышения лимитов.
