# Aisora — подготовка Vercel с телефона (этап 1)

## Что уже готово

Проект импортирован из `RollSatrs/Aisora`, ветка `main`, NestJS, Root Directory `./`.

Vercel автоматически устанавливает переменную `VERCEL=1`. При её наличии `src/main.ts` загружает **VercelAppModule** вместо локального **AppModule**.

- `GET /`: информация о тестовом облачном API.
- `GET /health`: публичная проверка запуска без доступа к АИС или базе данных.
- `POST /telegram/webhook`: при наличии отдельного Telegram-токена и корректного заголовка `x-telegram-bot-api-secret-token` отвечает на `/start` и `/ping`.
- Прочие команды получают сообщение о том, что полный облачный бот ещё не подключён.

**Важно:** этот этап сознательно не запускает PostgreSQL, Redis, BullMQ, браузер Playwright, `/connect`, `/sync` и отправку заданий. Не путать успешный деплой или `/ping` с полной готовностью АИС-синхронизации. Локальный запуск `pnpm start:dev` продолжает использовать прежний полный NestJS AppModule и Telegram polling.

## Что делать с телефона

1. В уже созданном проекте `aisora` на Vercel оставьте **Application Preset = NestJS**, **Root Directory = ./**, **Build & Output Settings** по умолчанию.
2. **Не добавляйте Redis** на первом шаге — он не используется в облачном тестовом модуле.
3. **Не добавляйте DATABASE_URL, REDIS_URL, CREDENTIALS_MASTER_KEY, пароль АИС или токен основного Telegram-бота.**
4. Нажмите **Deploy**.
5. Когда сборка станет Ready, откройте `https://<ваш-домен>.vercel.app/health`. Ожидается `status: ok`, `runtime: vercel`, `mode: webhook-smoke-test`, `aisSyncEnabled: false`.
6. При ошибке откройте **Deployments → последний деплой → Build Logs** и пришлите текст/скрин ошибки, без секретов.
7. GitHub → `RollSatrs/Aisora` → **Actions** → `Aisora checks` покажет результаты `pnpm typecheck`, `pnpm test` и `pnpm build`. Эта проверка не использует личные учётные данные.

## Проверка Telegram — отдельный этап

Чтобы избежать конфликта с работающим локальным polling, создайте **отдельного тестового Telegram-бота** через BotFather. Токен вводите только в **Vercel → Project Settings → Environment Variables**:

- `TELEGRAM_BOT_TOKEN`: токен **тестового** бота.
- `TELEGRAM_WEBHOOK_SECRET`: случайная строка 1–256 символов, разрешены буквы, цифры, `_` и `-`. Она должна совпадать с `secret_token`, переданным в Telegram `setWebhook`.

После добавления переменных выполните **Redeploy**, чтобы они применились к deployment. Затем настройте у Telegram адрес webhook:

`https://<ваш-домен>.vercel.app/telegram/webhook`

Для настройки используйте защищённый `setWebhook` вызов Telegram Bot API (POST) с этими данными. **Не вставляйте токен в сообщения ChatGPT, GitHub, скриншоты, URL публичных страниц или репозиторий.** Точный способ регистрации webhook с телефона определим после первого успешного `/health`.

Webhook возвращает 503, пока не заданы оба секретных параметра; при ошибочном токене заголовка — 401. Endpoint не выполняет синхронизацию или отправку в АИС.

## Что ещё требуется для полного Aisora

- Общедоступный из Vercel PostgreSQL с миграциями; секреты хранятся в настройках Vercel или безопасном хранилище.
- Отказ от хранения временных состояний диалогов в оперативной памяти serverless-функции (например, для `/connect`).
- Выполнение длительной Playwright-синхронизации в отдельном облачном задании, например GitHub Actions, с безопасной передачей запросов и результатов и без поддельных подтверждений сдачи.
- Перенос очередей/фонового планирования из Redis-процессов в совместимый с выбранной инфраструктурой исполнитель.
- Отдельное тестирование разрешённого доступа к АИС и ограничений облачного браузера.

До выполнения этих пунктов облачная версия — **только проверка HTTP и Telegram webhook**. Это не production-перенос данных и не замена уже работающей локальной Aisora.
