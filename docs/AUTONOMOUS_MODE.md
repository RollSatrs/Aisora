# Автономный режим

## Базовое правило

После окончания занятия по расписанию создаётся read-only проверка дисциплины с задержкой пять минут. Пример: занятие заканчивается в 12:05, проверка начинается не ранее 12:10 по `Asia/Almaty`.

## Поток событий

```text
Расписание → окончание пары + 5 минут → задача проверки
           → чтение релевантной дисциплины/недели
           → новые или изменённые наблюдения
           → дедупликация
           → уведомление / запрос уточнения
```

## Catch-up после простоя

При запуске сервис вычисляет занятия, завершившиеся после последнего успешного watermark. Для каждого пропущенного окна создаётся одна проверка. Очередь ограничивается по количеству и объединяет повторяющиеся проверки одной дисциплины/недели.

## Идемпотентность и конкуренция

- Ключ задачи: `account + course + lesson_end + check_type`.
- Уникальное ограничение предотвращает дубликаты BullMQ-задач.
- Redis-lock не заменяет уникальность в PostgreSQL.
- Повторный запуск разрешён, но side effects отсутствуют.
- Проверки одной учётной записи выполняются последовательно или с малой конкуренцией.

## Изменения заданий

Сохранять нормализованный снимок и хэш значимых полей: заголовок, неделя, срок, описание, список вложений и их метаданные. Новая версия создаётся при изменении хэша; косметические изменения HTML игнорируются. Удаление подтверждается несколькими наблюдениями, чтобы кратковременная ошибка загрузки не считалась удалением.

## Повторные попытки

| Ситуация | Политика |
|---|---|
| Временная сеть/5xx | Экспоненциальный backoff с jitter |
| 401/истёкшая сессия | Остановить аккаунт и запросить ручной вход |
| 403/ограничение | Остановить автоматизацию и уведомить владельца |
| CAPTCHA/MFA | Не обходить; ручной handoff |
| Изменение разметки | Открыть circuit breaker, создать диагностическое событие без персональных данных |
| Пустой раздел после прежних данных | Повторить позже; не удалять записи сразу |

## Ограничение нагрузки

- Проверять только дисциплину завершившегося занятия, а не весь аккаунт.
- Полная сверка — отдельно и редко.
- Вводить минимальные интервалы, jitter и дневной бюджет запросов.
- Не запускать массовое скачивание файлов.

## Уведомления

Отправлять уведомление только при новом задании, значимом изменении, подтверждённом долге, необходимости уточнения или ошибке сессии. Повторные одинаковые события подавляются по fingerprint и cooldown.
