# Aisora MVP

Aisora — read-only-first помощник студента. Production-конфигурация использует `AbuUniversityAdapter` с автоматическим повторным входом, ограничением частоты и исключительно читающими операциями. `MockUniversityAdapter` используется только тестами.

## Реализовано

- NestJS modular monolith и REST API;
- Telegram-команды `/start`, `/status`, `/sync`, `/tasks`, `/settings` и клавиатура;
- тестовая синхронизация дисциплин, недель, СРО, СРСП, лабораторных, истории отправок и оценок;
- evidence-based статусы, версии заданий и дедупликация;
- понятный Telegram-отчёт по дисциплинам: долги прошедших недель, текущая неделя, будущие, выполненные и требующие проверки;
- автономный режим: initial-sync guard, post-class +5 минут, catch-up, stop/resume и idempotency;
- BullMQ-очередь проверок и отдельная неактивная очередь старых задолженностей;
- PostgreSQL/Drizzle-схема и первая миграция;
- Docker Compose для PostgreSQL и Redis;
- тесты десяти обязательных сценариев.

Реальный read-only ABU-адаптер основан на подтверждённом интерфейсе авторизованного кабинета. Учётные данные шифруются AES-256-GCM отдельным master key, сессия находится во внешнем браузерном профиле, а приложение не подменяет ошибки доступа mock-данными.

## Как работает бот

```text
Пользователь → /connect в Telegram → зашифрованное хранилище PostgreSQL
                                      ↓
Команда /sync или очередь BullMQ → AbuUniversityAdapter → ABU AIS (только чтение)
                                      ↓
                      дисциплины, недели, задания, отправки, оценки
                                      ↓
                         PostgreSQL → отчёт и уведомления Telegram

Redis/BullMQ → плановые проверки после занятий → тот же безопасный sync-процесс
Истекла AIS-сессия → автоматический вход → новая сессия → продолжение sync
```

Бот сам считает статусы только на основе фактов из AIS: найдено ли задание, есть ли подтверждённая отправка и оценка. Он не выполняет и не отправляет задания.

Долгом считается только обязательная работа недели меньше текущей, для которой AIS не показывает подтверждённую отправку или оценку. Недели 1–8 относятся к первому периоду, 9–15 — ко второму; 8-я и 15-я недели отмечаются как рубежный контроль. Будущие задания долгами не считаются. «Требует проверки» означает недостаток доказательств и выводится отдельно от долгов.

## Требования

- Node.js 22+
- pnpm 10+
- Docker с Compose — для PostgreSQL и Redis

## Запуск

```bash
cp .env.example .env
pnpm install
openssl rand -base64 32 # результат поместить в CREDENTIALS_MASTER_KEY
pnpm db:migrate
pnpm start:dev
```

Если PostgreSQL и Redis уже запущены локально, Docker не нужен: достаточно указать их адреса в `DATABASE_URL` и `REDIS_URL`.

Без `TELEGRAM_BOT_TOKEN` polling Telegram отключён, но REST API доступен. Токен хранится только в `.env`.

## Подключение ABU AIS

1. Получите разрешение на read-only автоматизацию и установите `AIS_AUTOMATION_APPROVED=true`.
2. Создайте `CREDENTIALS_MASTER_KEY` командой выше. Не меняйте и не теряйте этот ключ после сохранения данных.
3. В личном чате с ботом выполните `/connect` и один раз введите логин и пароль AIS. Сообщения удаляются сразу, а в PostgreSQL сохраняется только шифротекст.
4. Выполните `/sync`. Для каждого Telegram-аккаунта используется отдельный постоянный Chrome-профиль вне репозитория.
5. После истечения сессии адаптер сам войдёт повторно и продолжит синхронизацию.

AIS может отвечать медленно: по умолчанию элементы и переходы между страницами ожидаются до 5 минут, а вход — до 90 секунд. Значения настраиваются через `AIS_PAGE_TIMEOUT_MS`, `AIS_NAVIGATION_TIMEOUT_MS` и `AIS_LOGIN_TIMEOUT_MS`.
При `AIS_BROWSER_HEADLESS=false` владелец видит работу Chrome во время синхронизации. Telegram-сообщение одновременно обновляется по фактическим этапам загрузки; переход продолжается только после появления подтверждённого элемента следующей страницы.

Навигация использует безопасный адаптивный подход: распознаёт пункты интерфейса по доступному имени и смысловому тексту, раскрывает нужный раздел и проверяет ожидаемое состояние страницы. Координатные клики и свободный выбор действий запрещены; агент может переходить только по read-only маршрутам и не взаимодействует с отправкой сообщений, заданий или файлов. В отдельном Chrome-профиле отключены окна сохранения и проверки утечки паролей, способные перекрывать AIS.

### Гибридный навигатор

1. Playwright собирает только видимые ссылки и кнопки, не включая поля логина и пароля.
2. Семантические правила сначала ищут известную read-only цель без обращения к модели.
3. Если интерфейс незнаком, локальная `qwen2.5:3b-instruct` через Ollama выбирает идентификатор из наблюдаемого списка.
4. Safety policy повторно отклоняет создание, изменение, сохранение, отправку, загрузку, удаление, выход и переход на чужой домен.
5. Исполнитель нажимает разрешённый элемент и проверяет ожидаемое состояние страницы. При неоднозначности действие не выполняется.

Локальный fallback включается через `AIS_AGENT_MODEL_ENABLED=true`. По умолчанию используется `http://127.0.0.1:11434/api/chat`; отправка представления AIS на внешний endpoint блокируется, пока явно не задано `AIS_AGENT_REMOTE_DATA_APPROVED=true`.

Подробный порядок обхода дисциплин, недель, СРСП, СРО, сообщений и вложений описан в [`docs/SYNC_ALGORITHM.md`](docs/SYNC_ALGORITHM.md). Настройка `/labfocus` позволяет включать глубокое чтение лабораторных отдельно для каждой дисциплины; это уменьшает длительность синхронизации и локальные вычисления.

Адаптер читает только подтверждённые разделы. Он не нажимает «Создать», не выбирает файлы и не взаимодействует с формами отправки. Для неоценённых СРО читается только история уже загруженных файлов.

## Безопасность

- не добавляйте пароли, bot token, cookies или browser storage в репозиторий;
- используйте `/connect` только в личном чате; Telegram всё равно получает текст до удаления сообщения;
- не записывайте `CREDENTIALS_MASTER_KEY` в репозиторий и резервируйте его отдельно от базы;
- содержимое AIS считается недоверенным;
- Submission Connector отсутствует и отправка в AIS невозможна;
- лабораторные требуют реального выполнения, фиктивные доказательства запрещены.

## Структура

```text
src/
├── api/             HTTP API
├── autonomous/      планирование и catch-up
├── bot/             grammY
├── database/        Drizzle schema
├── domain/          доменные типы
├── persistence/     порт, PostgreSQL и in-memory test adapter
├── queue/           BullMQ queues/workers
├── sync/            initial sync и статусы
├── auth/            шифрование учётных данных
└── university/      реальный адаптер и тестовый MockUniversityAdapter
```

Рабочее приложение использует PostgreSQL-репозиторий и `AbuUniversityAdapter`. Для включения после одобрения установите `AIS_AUTOMATION_APPROVED=true`; при отсутствии/истечении сессии выполняется автоматический вход из зашифрованного хранилища. In-memory repository и `MockUniversityAdapter` используются только в unit/integration тестах.
